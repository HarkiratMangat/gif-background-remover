## THE GATE ON GROUP C — read before planning any session

**Items C1–C4 fail for one reason, and it is a missing population, not a missing idea.** Measured over the 719-asset corpus:

- **30 of the 33 detection misses are hard-alpha cutouts** where both transition-band rules correctly abstain, so `composited_color_count` is the *only* rule left to decide.
- Against those, the corpus holds **21 antialiased hard-alpha cutouts, and 15 of them are alpha-only masks** excluded from every colour rule. **Six usable negatives against thirty misses, on the exact path where the failure lives.**
- In the size band that matters (400–3,000 art pixels) the corpus holds **99 pixel-art assets and exactly ONE antialiased asset.**

That single asset is the entire basis for the current threshold margins. Any measure built for C1–C4 will score beautifully and be untestable — which is exactly how `min_share` reached 0.972 recall with zero false positives and turned out to be measuring image size (§29.12).

### What to acquire

**Target 20 minimum, 30–40 comfortable.** Drop into a new folder under `local/`; Task C0 labels and registers them.

| property | value | why, and what breaks without it |
|---|---|---|
| size | **32–128 px longest side** | The failures live at sprite scale. A 512px icon has thousands of colours and is trivially separable. |
| alpha | **transparent background, ~70%** of the set | 30 of 33 misses are hard-alpha cutouts; a negative must share that path to falsify anything there. The rest opaque-on-a-background, which exercises the tool's primary job and the 16-colour floor. |
| colour | **multi-coloured, NOT monochrome glyphs** | A single flat RGB triggers `_alpha_only_source`, every colour rule abstains, and the asset tests nothing. 15 of the 21 existing hard-cutout negatives are wasted this way. |
| edges | **genuinely antialiased** — smooth curves and diagonals with intermediate pixels | If the edges are blocky it is pixel art and belongs in the other class. |
| provenance | **authored or exported AT that size — never downscaled** | Not fussiness. Downscaling the existing emoji to 64px produced 128–1,371 distinct colours over ~1,500 art pixels — nearly one unique colour per pixel, a resampling artefact no real icon has. It made the test far too easy and would have "confirmed" a wrong measure (§29.12). |
| palette | **spread, especially 16–64 colours** | That band is the exact overlap. **Small GIFs are the most valuable single kind**, because GIF quantizes to ≤256 colours and lands there naturally. |
| animation | **static is fine** | Not a gap: the corpus already holds 91 animated antialiased assets against 57 static. A few small animated GIFs still help Task C4's cross-frame angle, but do not go hunting for them. |
| variety | curves, diagonals, gradients, soft shadows, thin strokes | Twenty variants of one icon is one data point. |

**Where these come from:** icon packs exported at 32–128px (Flaticon, Icons8, Noun Project) · **Discord/Slack custom emoji — usually 128px, often GIF, ideal** · favicon sets · small UI icon sets · non-pixel-art sticker packs.

**A second, smaller corpus** unblocks one more item: a handful of **gradient-heavy** assets (smooth ramps, glows, soft shadows) for Task A6, the gifsicle dither re-test.

- [ ] **Step 1: Search for a source where the band actually helps.** A source whose own alpha leaves a real matte fringe: `alpha == 0` at the boundary with background-coloured pixels just outside it, and that colour absent from the interior.

```bash
python3 - <<'PY'
import sys, warnings
warnings.filterwarnings('ignore')
import numpy as np
from PIL import Image
from scipy import ndimage
sys.path.insert(0, 'scripts/harness')
from populations import iter_assets
import importlib.util
sp = importlib.util.spec_from_file_location('m', 'scripts/remove_gif_background.py')
m = importlib.util.module_from_spec(sp); sp.loader.exec_module(m)
hits = []
for k, p, pop, lab in iter_assets(include_excluded=True):
    try:
        im = Image.open(p); im.seek(0)
        st = m.get_source_transparency_mask(im)
        if st is None or not st.any(): continue
        rgb = np.array(im.convert('RGB')); bg = m.detect_bg_color(rgb)
        scope, band_applied, why = m.build_source_alpha_scope(st, rgb, bg, 15, 2)
        if not band_applied: continue
        ring = scope & ~st
        gained = int((ring & m.color_mask(rgb, bg, 60)).sum())
        if gained: hits.append((gained, k))
    except Exception: pass
hits.sort(reverse=True)
print(f'{len(hits)} assets where the ring removes something the source alpha did not')
for g, k in hits[:10]: print(f'   {g:>7} px  {k[-52:]}')
PY
```

**Files:**

**Interfaces:**
- Consumes: nothing from Group A.
- Produces: `compute_alpha_mask(rgb_out, protected, args, removal_scope=None, rgb_key=None)` — `rgb_key` defaults to `rgb_out`, so every existing caller is unchanged.

`analyze()` composites every frame carrying partial alpha; `process()` still builds `rgb_frames_raw` with a bare `convert('RGB')`. **The flags are chosen from one image and the removal acts on another.** Measured: `color_mask` at the real removal reach disagrees on **41 of 338** partial-alpha sources, worst **18.41% of a frame**.

⚠️ **Do NOT composite `rgb_frames_raw` itself.** Two reasons, both measured. The output must carry original art colours — compositing bakes the background into the pixels you write. And the composite masks **MORE**: on `love_emoji_128.webp` it removes **3,017 additional pixels**, which are half-transparent ones whose blended colour reads as background — exactly the artwork `--recover-fade-alpha` exists to reconstruct.
