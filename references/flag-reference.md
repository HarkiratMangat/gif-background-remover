# Flag reference — the prose behind the usage block

`SKILL.md` lists the flags and the decisions that pick between them. This file explains what the individual quality/output flags actually do, for when a flag's name is not enough.

**Edge feathering** (default on): a hard color-distance cutoff leaves a jagged/staircase boundary wherever the source art had smooth antialiasing, since GIF only supports on/off transparency per pixel. The script instead estimates a continuous alpha in a transition band around the cutoff (color-unmixing against the background), de-fringes those edge pixels, and converts the band to a binary transparent/opaque pattern using a spatially fixed Bayer dither — so the edge reads as soft rather than blocky, without flickering between frames. `--feather-band-multiplier` (default 4.0, i.e. 4x `--tolerance`) widens/narrows the transition band. `--no-feather` only if the user explicitly wants the old hard-cutoff look (e.g. true pixel-art style).

**Crop** (default OFF): standalone `--crop` crops to the transparent bounding box without any other tier step. Any `--compress` tier crops automatically regardless of this flag.

**Output size reporting**: every run prints final dimensions and file size in KB to stderr — use this instead of a separate size check, and as the signal for whether file-size optimization (below) is worth raising.

**Preview contact sheet** (`--preview <path.png>`, off by default): saves a single PNG with evenly-sampled frames composited over a checkerboard, side by side. Pass it on the same run that produces the final GIF.

**Region flags — coordinates are in SOURCE pixels.** `--protect-region`, `--remove-region` and `--translucent-region` share one spec syntax (`circle:cx,cy,r` or `rect:x,y,w,h`, several joined by `;`) and are all applied BEFORE `--crop`, `--resize-max-dim` and `--square-pad`. Measure the numbers off the input file, never off a cropped or resized output — nothing can detect a mis-measured region, it will simply act on the wrong rectangle.

**`--translucent-region`** makes a named area SEE-THROUGH rather than kept or removed, for glass, a window, a transparent bag — art where one colour is background in one place, opaque design in another, and translucent material in a third. `--translucent-alpha` sets the level (0.0-1.0, default 0.35) and `--translucent-color` picks which colour inside the region is affected (default: the background colour). Two restrictions keep a hand-drawn rectangle from doing collateral damage: only pixels matching that colour are touched, so the CONTENTS of the glass stay opaque; and only already-opaque pixels are lowered, so an antialiasing ramp or a recovered fade keeps its own alpha. Requires a `.webp`/`.avif`/`.apng` output. It has to be named by hand for a measured reason — see `references/lessons.md` §27, where the see-through pocket and the opaque one turn out to be byte-identical in colour AND both fully enclosed by the same outline.

**Already-transparent sources: `--source-alpha-band`, `--ignore-source-alpha`.** When the source's own alpha already stands in for its background, colour-based removal is confined to the region that alpha covers, because there is no background colour left to key on — `detect_bg_color` would read the bytes stored *under* the transparent pixels, which is padding, and on real sprites that padding is `(0,0,0)`, the same value as the artwork's own outlines. Two conditions must both hold before the restriction engages: the transparent region reaches the frame border (so it is the outside, not a punched hole), and the modal colour under it matches the detected background (so the background really is padding rather than paint). `--source-alpha-band PX` (default 2) is how far past that region removal may reach — the ring where a leftover matte fringe from an *earlier*, imperfect cut lives — and it is **dropped automatically whenever the background colour also occurs in the artwork away from the boundary**, because then the ring is the outline. `--ignore-source-alpha` removes by colour across the whole frame regardless; it is the escape hatch for a source whose own alpha is wrong, and it restores the pre-v5.5.0 behaviour that destroyed up to 71% of a sprite's artwork. Every run that engages the restriction says so on stderr, with the reason. `references/lessons.md` §28.14

**`--format apng`** (or a `.apng`/`.png` output) is the third 8-bit-alpha container: lossless, and the only one with no optional dependency — Pillow's PNG writer has always handled `save_all`. It is the largest of the three, so `--recommend` still ranks WebP and AVIF ahead of it; choose it when the destination wants PNG specifically. A single-frame source writes an ordinary static PNG. `--target-kb` drives it through the same resolution/frame cascade minus the quality rung, since APNG has no quality setting.
